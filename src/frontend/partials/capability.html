It takes an action request and what has been used today, and hands back allow, hold or deny with the rule that produced it. Money is bounded by amount; an outbound call is bounded by which hosts it may reach and which methods change something. It reads no clock, no database and no network, so every rule in it can be tested on its own.

Asking about every write buries the one that mattered. So you name the methods a model may judge, and it decides those — filing an issue runs, repointing a DNS record still stops. It never sees a call the rules already refused, and it never reads the agent's own description of what it is doing. That sentence exists to persuade, and persuasion is the attack.

An action over the limit stops where it stands, emails a named human, and waits. The decision is a POST from a page whose token is single-use and stored only as a hash, and nothing downstream is contacted until someone says yes.

Every state change appends an event — requested, evaluated, held, approved, executed — and nothing is ever edited or removed. Keys and tokens are stripped as the row is written, not as it is read.

Approach

How an action moves

  1. 01

    Request

    The agent calls requestAction with a type, an amount and a recipient. Nothing has moved yet — the call asks for permission, it does not give an instruction.

  2. 02

    Evaluate

    The policy engine measures the amount against the $50.00 per-action limit, the $2,000.00 daily cap and the recipient allowlist. It returns a single decision together with the reason that produced it.

  3. 03

    Settle

    In bounds it executes at once and the result is recorded. Over the limit it holds for a human; past the $1,000.00 ceiling it is denied, and no approval can move it.
