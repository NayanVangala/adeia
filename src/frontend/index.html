The shape of it

Three layers, and each one assumes the last can be lied to

01 — Schema

Refuse before you think

https only. No private, loopback or link-local address. A body small enough that a person can read it. These are cheap and they run first, so the expensive checks never see the obvious cases.

02 — Policy

A pure function that cannot cheat

Reads no clock, no database, no network. Today's spend is passed in rather than looked up, which is what lets every rule be tested on its own with no fixtures and no fake timers.

03 — Adapter

Check again at the last moment

Re-resolves the hostname as the call goes out and refuses if it now points somewhere private. A name that was public when you wrote the policy can point at the metadata endpoint by the time the request runs.

The problem

An agent with an API key has no idea what it is about to cost you

DELETE /zones/{id} and GET /zones differ by one word, and one of them ends a website. The model cannot tell the difference in any way you can rely on, and by the time it has run there is nothing to inspect — the thing you would inspect is gone.

Without a fence

  • A retry loop spends the budget in ninety seconds.
  • A confused agent deletes the wrong record and says it succeeded.
  • Prompt-injected text points a call at a host you never approved.
  • Nothing is written down, so nobody can say what happened.

With one

  • Over the limit, it stops and asks a person.
  • Off the allowlist, it is refused before any request goes out.
  • Private addresses are blocked at three separate layers.
  • Every decision is in an append-only trail, with its reason.
The model's part

A model decides, but only inside a band you opened

Stopping every write for a human buries the approval that matters under the ones that do not. So a classifier judges the ordinary ones — and it is never consulted about a call the fence already refused.

It cannot open a door you shut

Every deny rule runs first. By the time a model can be asked, the host allowlist, the private-address check and the daily cap have already answered. Injected text can win inside a band you opened. It cannot open one.

It never reads the excuse

The classifier sees the method, the URL and the body — never the agent's description of what it is doing. That sentence is written by the party under evaluation and exists to persuade. The endpoint cannot be talked around.

Failing means asking

Timeout, malformed answer, dead key, a verdict nobody recognises — all of them send the action to a person. A classifier that cannot answer must never mean yes.

DELETE stays with a person forever, whatever any model concludes. That is a floor, and it is yours.

How it works

What happens between asking and doing

  1. 01

    The agent asks

    It calls requestAction with an idempotency key. It holds no card and no credential of its own — only the ability to ask.

  2. 02

    The rules answer

    Deny rules first, always. A $2,000,000 payment to an unknown recipient is refused outright rather than offered to a tired human as a button to click.

  3. 03

    A person decides, if one must

    An email, and a page that states what the request will actually do in plain words — derived from the method and URL, never from the agent's own description of itself.

  4. 04

    It runs, or it does not

    The adapter re-resolves DNS, refuses redirects, and never returns the request headers — that is where the credential is, and an approval page gets screenshotted.

  5. 05

    It is written down

    Append-only, secrets stripped at write time, and the trail says whether a person or a model decided. Those must never read the same.
