    02 — Lifecycle

    Four states, and only one needs you.

    Every action your agent requests walks the same path. Most reach the end without anyone looking. The ones that matter stop at step three.

    1. Requested

      Your agent calls requestAction with a type, an amount, and a recipient. Nothing has happened yet.

    2. Evaluated

      The policy engine checks the amount against your per-action limit, your daily cap, and your recipient allowlist. It returns a decision and the reason for it.

    3. Held

      Over the limit means the action stops here. A human gets an email showing the amount, the recipient, and which rule was crossed. Nothing downstream has been contacted.

    4. Executed

      On approval, or immediately if the action was in bounds, Adeia calls the integration and records the result. Every step above is already in the audit log.

    03 — SDK

    One method. Three possible answers.

    The SDK returns a decided action, not a promise you have to babysit. If it comes back held, waitForAction blocks until the human decides.

    Amounts are integer cents. There are no floats anywhere in the money path.

    agent.ts
    import { AdeiaClient } from "@adeia/sdk";

const adeia = new AdeiaClient({ apiKey: process.env.ADEIA_API_KEY });

const action = await adeia.requestAction({
  type: "payment",
  params: {
    amountCents: 50000,
    currency: "usd",
    recipient: "acct_contractor",
    description: "Q3 design work",
  },
});

// "executed" | "pending_approval" | "denied"
if (action.status === "pending_approval") {
  const settled = await adeia.waitForAction(action.id);
}
    04 — Policy

    The fence is a few numbers you own.

    Set a per-action limit, a daily cap, a hard ceiling, and an optional recipient allowlist. Adeia answers every request against them and tells you which rule decided it.

    A denial is not an error. It is a policy outcome, returned with the figure that triggered it.

    Amount Recipient Decision Because
    $25.00 acct_cloudhost Executed Within policy.
    $50.00 acct_cloudhost Executed Exactly on the per-action limit. The limit is inclusive.
    $500.00 acct_contractor Held Over the $50.00 per-action limit. Waiting on a human.
    $1,200.00 acct_contractor Denied Over the $1,000.00 hard ceiling. No human can approve past this.
    $40.00 acct_unknown Held Inside every limit, but the recipient is not on the allowlist.
    05 — Audit

    You can always answer who let that through.

    Each state change writes an append-only event. Requests, decisions, the reason behind them, who approved, and what the integration returned.

    Secrets are stripped at write time, so the log is safe to hand to whoever asks for it.
